Neural Ansatz

Wave-function ansatze

QuantumNeuralStates.AnsatzType — Type
AnsatzType

Abstract type for specifying how the wave-function NeuralAnsatz is defined with respect to neural network representation. The representation should reflect how many outputs neural network predicts.

Each defined AnsatzType also needs to have defined dispatched functions of psi!, log_psi!, and init_gradient_seed!!

See also LogPsi and LogPsiSignTanh.

source
QuantumNeuralStates.LogPsi — Type
LogPsi

Type of AnsatzType, using neural network with one continous output (identity activation). This output (noted as out[1]) should represent out[1] = log(ψ).

\[\psi = \exp(\text{out}[1])\]

Variables

  • num_outputs: how many outputs this ansatz expect.
source
QuantumNeuralStates.LogPsiSignTanh — Type
LogPsiSignTanh

Type of AnsatzType allowing representing sign phase +-1, 0. It uses two neural networks outputs. First output (noted as out[1]) is continous number ( identity activation) and second output (noted out[2]) is using tanh (or tanh_fast) activation. The final wave-function is then represented as:

\[\psi = \exp(\text{out}[1]) \text{out}[2] = \sigma \exp(\text{out}[1]) \text{abs}(\text{out}[2])\]

where σ represents sign of the wave-function and exp(out[1]) abs(out[2]) represents amplitude of wave-function.

Variables

  • num_outputs: how many outputs this ansatz expect.

QuantumNeuralStates.psi! — Function
psi!(ansatz, vals) -> ψ
psi!(ansatz, logψ, signψ) -> ψ

Compute the wave-function values ψ, in-place. Each AnsatzType must define its own psi!(::AnsatzType, ansatz, logψ, signψ).

The first form takes the raw network outputs vals and calls log_psi! internally. The second form takes logψ and signψ exactly as returned by log_psi!, for when it has already been called.

Both forms overwrite their input with ψ, so the result must not be passed to psi! or log_psi! again.

See LogPsiSignTanh for a multi-output and LogPsi for a single-output example.

source
QuantumNeuralStates.log_psi! — Function
log_psi!(ansatz, vals) -> log|ψ|, sign(ψ)

Compute log|ψ| and sign(ψ) from the network outputs vals, in-place. Each AnsatzType must define its own method.

Used in vmc_sample! and calculate_local_energy! for wave-function ratios. Call it only once on the same vals: it overwrites the raw outputs, so a second call would process already-processed values. To get ψ afterwards, pass the results to psi! as psi!(ansatz, logψ, signψ).

See LogPsiSignTanh for a multi-output and LogPsi for a single-output example.

QuantumNeuralStates.init_gradient_seed! — Function
init_gradient_seed!(ansatz, seed) -> seed

This function ensures correct gradient seed values in backpropagation. It returns correct AnsatzType dispatch function that returns the gradient seed. It is important that for every ansatz_type this function is defined for correct backpropagation.

Notes

In the [apply_loss_mode!] function, all derivatives of loss functions w.r.t. log|ψ| are defined here. This is typical procedure in neural networks field.

\[\frac{\partial \mathcal{L}}{\partial \text{log}(\text{abs}(\psi))} = \frac{\partial \mathcal{L}}{\partial \psi}*\psi\]

In cases where wave-function ansatz is more complicated (example LogPsiSignTanh) the derivatives can have extra terms w.r.t. neural network outputs. From the example we can define those derivatives as

\[\begin{aligned} \frac{\partial \mathcal{L}}{\partial \text{out}[1]} &= \frac{\partial \mathcal{L}}{\partial \psi} * \frac{\partial \psi}{\partial \text{out}[1]} = \frac{\partial \mathcal{L}}{ \partial \psi} * \psi \\ \frac{\partial \mathcal{L}}{\partial \text{out}[2]} &= \frac{\partial \mathcal{L}}{\partial \psi} * \frac{\partial \psi}{\partial \text{out}[2]} = \frac{\partial \mathcal{L}}{ \partial \psi} * e^{\text{out}[1]} = \frac{\partial \mathcal{L}}{\partial \psi} * \frac{\psi}{\psi} * e^{\text{out}[1]} = \frac{\partial \mathcal{L}}{\partial \psi} * \psi / \text{out}[2] \end{aligned}\]

On this example we can see that if the derivative of loss function w.r.t. neural network outputs are equal to ∂L/∂ψ * ψ, than everything is accounted in apply_loss_mode! already (the seed for such output can be just filled with ones). Nevertheless, if there are some extra terms as 1/out[2] in the second equation of the example, this extra term needs to be accounted in init_gradient_seed!.

Neural Ansatz

QuantumNeuralStates.NeuralAnsatz — Type
NeuralAnsatz(ansatz_type, hamiltonian, model, batch_size; kwargs...) <: Gutzwiller.AbstractAnsatz

A neural network-based variational ansatz for use with Rimu's FCIQMC. Wraps a Chain neural network model and manages the buffers needed for batched evaluation and importance sampling.

Arguments

  • ansatz_type: it is AnsatzType which determine how the wave-function ansatz, using neural network outputs, should looks like.
  • hamiltonian: hamiltonian defined in Rimu.
  • model: a Chain neural network model.
  • batch_size: number of configurations evaluated in a single forward pass.

Keyword Arguments

  • input_scale_func: scaling function for inputs (default: identity).
  • max_norm: maximum particle number for input normalisation. Must be positive if provided.
  • multiforward_buffer: can be set with Int number. This number would determine usually bigger batch forward passes. See MultiForwardBuffer.
  • mean_field: if set true the mean-field would add to neural network wave-funciton evaluation. Needs to be manually defined, see MeanField.
  • truncation: can be used for input space truncation. See TruncationBuffer.
  • neuron_statistics: Can be activated with true (statistics would be print out to terminal), or (NOT WORKING - filename::String to be saved in external file). See neuron_statistics.
  • jacobian_statistics: Can be activated with true (statistics would be print out to terminal), or (NOT WORKING - filename::String to be saved in external file). See jacobian_statistics.

Example

julia> M = 10
julia> N = 10
julia> batch = 1024
julia> addr = BoseFS{missing, M}()
julia> H = FroehlichPolaron{Float32}(addr; D=1, mode_cutoff=N)
julia> input = OccupationEncoding((M,), H)
julia> model = build_model("FCNN", input, [M, 100, 100, 100, 1], tanh_fast; batch=batch)
julia> ansatz = NeuralAnsatz(LogPsi(), H, model, batch)

Fields

  • ansatz_type: it is AnsatzType which determine how the wave-function ansatz, using neural network outputs, should looks like.
  • hamiltonian: hamiltonian defined in Rimu.
  • model: a neural network type of Chain used to evaluate the ansatz.
  • logψ_centering: this is max value centering over batched model output connected with wave-function amplitude - log|ψ| (fighting the gauge invariant for multiplication of wave-function with arbitrary number coefficient)
  • addrs_buffer: dynamically filled buffer of addresses, used during Rimu FCIQMC importance sampling.
  • result_buffer: dynamically filled buffer of network outputs, paired with addrs_buffer during FCIQMC importance sampling.
  • result_dict: cache mapping of results of neural network used during Rimu FCIQMC importance sampling
  • first_iter: flag indicating whether the FCIQMC iteration is the first; used to control buffer initialisation logic.
  • input_scale_func: a function applied to raw occupation inputs before they are fed to the network. Defaults to identity (uniform spread). Use e.g. sqrt to compress large occupation numbers and give smaller values relatively more importance.
  • max_norm: Maximum total particle number in the system. When set, inputs are normalised so the highest possible occupation maps to 1, keeping all inputs in [0, 1]. nothing disables this normalisation - by default.
  • normalisation: Scale factor derived from max_norm. Ensures that if neural networks load pre-computed weights, they value invariant regardless the normalisation.
  • multi_forward_buffer: if active it holds additional MultiForwardBuffer. This allows to do forward pass with arbitrary batch size.
  • meanfield: allows using mean-filed estimate with neural network output. See MeanField.
  • truncation: allows input truncation for graduate training in smaller dimensions. See TruncationBuffer.
  • neuron_statistics: allows to print out statistics about neural network. Either, to terminal or external file. See neuron_statistics.
  • jacobian_statistics: allows to print out statistics about jacobian (per-sample gradient). Either, to terminal or external file. See [jacobian_statistics`](@ref).

QuantumNeuralStates.MeanField — Type
MeanField(H; backend = KernelAbstractions.CPU())

If mean-field is enabled in NeuralAnsatz, then this structure adds mean-field log-amplitude on top of the neural-network output,

\[\log\psi(n) = \log\psi_{\mathrm{NN}}(n) + \log\psi_{\mathrm{MF}}(n).\]

The mean field is defined by a function mf_func(o, params, T) that returns the log-amplitude (of type T) of a configuration with occupation numbers o = onr(addr), together with its parameters params. Both are returned by a Hamiltonian-specific method of _choose_meanfield_function. Parameters are built once on the CPU and moved to backend; the evaluation runs as a kernel on that backend.

Arguments

  • H: Rimu Hamiltonian for which the mean field is constructed.

Keyword Arguments

  • backend: KernelAbstractions backend on which the parameters live and the kernels run, e.g. KernelAbstractions.CPU() (default), MetalBackend(), or CUDABackend(). Must match the backend of the arrays passed to (mf). Resolved in NeuralAnsatz structure.

Notes

  • To add a mean field for a new Hamiltonian, define a function mf_func(o, params, T) and a method _choose_meanfield_function(H::Rimu.Hamiltonian; backend) returning (mf_func, params).
  • params should be a Tuple or NamedTuple of arrays and scalars, so it is converted to device arrays automatically when passed to the kernel.
  • mf_func runs inside a kernel: it must not allocate and may only call device-compatible functions (e.g. no loggamma; use a look-up table instead).
  • The mean field does not depend on the network parameters θ, so it does not enter the Jacobian.

QuantumNeuralStates.TruncationBuffer — Type
TruncationBuffer(H, k, backend; type=:center, metric=:l1)

This buffer is part of NeuralAnsatz and it introduce input truncation.

Arguments

  • H: Hamiltonian defiend in Rimu. It is needed for extracting system geometry.
  • k: this value define how small truncation I want to use.
  • backend: where the mask should live (CPU/GPU).

Keyword Arguments

  • type: define a switch between different truncation schemes. For now only :center (truncate input space from center futher) is defined.
  • metric: define another parameter involving geometry of truncation. (how I determine nearest closest neighbours)

Note

  • type options: :center
  • metric options: :l1, :l2, :linf

QuantumNeuralStates.SCALE_FUNCTIONS — Constant
SCALE_FUNCTIONS

Registry of the input scaling functions available for NeuralAnsatz. Maps a name (Symbol) to the function that is applied to each occupation number before it enters the network,

\[x_m = f(n_m) \cdot \mathrm{normalisation} ,\]

see _prepare_input_kernel! and _prepare_input_stream_kernel!.

Available functions

  • :identity: raw occupation numbers.
  • :sqrt: √n.
  • :log1p: log(1 + n).
  • :sqrtlog1p, :log1plog1p: composed variants that compress large occupations more strongly.

Adding a new function

Define a scalar function and register it under its own name:

myscale(x) = ...
SCALE_FUNCTIONS[:myscale] = myscale      # or add it to the definition below

Requirements

  • The function is called inside GPU kernels on Float32 values: it must be scalar, type-stable (Float32 → Float32) and device-compatible (no allocations, no calls that only exist on the CPU).
  • The key must equal the function's name, Symbol(nameof(f)). save_master stores the function by its name, and load_master looks it up here, so a mismatch prevents a saved model from being loaded.

QuantumNeuralStates.prepare_input! — Function
prepare_input!(na::NeuralAnsatz, addr, x) -> x
prepare_input!(na::NeuralAnsatz, addrs::AbstractVector, x) -> x

Write the scaled occupation numbers input_scale_func(onr(addr)) * normalisation into the occupation channel of the input buffer x (shape of the Chain input). A single addr fills every column; a vector addrs fills one column per address.

Runs as a KernelAbstractions kernel on the device of x:

  • CPU: x an Array, addrs a Vector
  • GPU: x a device array (e.g. model.x), addrs a device array of addresses

Addresses must be isbits for GPU use, and input_scale_func must compile on the device. Columns beyond length(addrs) are left untouched.

QuantumNeuralStates.compute_logψ — Function
compute_logψ(ansatz, addr) -> logψ
compute_logψ(ansatz, addr, multi_forward_buffer) -> logψ

Evaluate the Neural Network for the configuration(s) addr: the occupations are written into the input buffer with prepare_input!, then a forward pass through the network gives its output.

Final wave-function representation can be done using log_psi! for log represantation or using psi! for full wave-function representation. See also AnsatzType.

If dispatched with multi_forward_buffer it allows for computation in arbitrary batch sizes. See MultiForwardBuffer.

QuantumNeuralStates.multi_compute_logψ! — Function
multi_compute_logψ!(ansatz, addrs_buf, vals_buf, offsets) -> vals

This function evaluates the Neural Network on all valid off-diagonal addresses, with an arbitrary number of them. All valid off-diagonals are treated as one continuous stream, which is cut into forward passes.

Each forward pass consists of:

  1. _prepare_input_stream_kernel! — fills the network input xe with the occupations of the next n off-diagonals of the stream,
  2. the forward pass of the model,
  3. a contiguous copy of the n outputs into vals, in stream order.

The outputs are stored packed, in stream order: column g of vals holds the outputs of stream position g. The valid part is view(vals, :, 1:total) with total = last(offsets); everything beyond is unused capacity (dummies).

Variables

  • ansatz: structure of NeuralAnsatz.
  • addrs_buf: GPUGrowRowBuffer holding off-diagonal addresses as (K, B): column b holds the off-diagonals spawned by parent address.
  • vals_buf: GPUGrowColumnBuffer for the network outputs (n_out, capacity); grown to at least total columns.
  • offsets: device vector of length B, the cumulative number of valid off-diagonals per column (cumsum of the counts). Column b holds offsets[b] - offsets[b-1] valid off-diagonals (with offsets[0] = 0).

Indices

  • j: column of the network input xe (and output raw) in the current forward pass, 1 … n. Every thread of a kernel handles one j.
  • offset_current: number of stream positions already processed by earlier passes (0, fwd, 2fwd, …).
  • g = offset_current + j: global position in the stream of valid off-diagonals, 1 … total, continuous over all passes.
  • b = _find_column(offsets, g): column of addrs that stream position g belongs to (see _find_column).
  • k = g - _column_start(offsets, b): row of that off-diagonal within column b (see _column_start).

b and k are only needed to read the address addrs[k, b]; the output position is g itself.

Note

The forward size fwd is the number of columns of the input buffer: the MultiForwardBuffer buffer_size if present, otherwise the model batch size.
